# AI 计算能力诊断与训练教练

## 1. 文档目的

本文档定义在 XC 速算练习工具中加入“个人计算能力诊断与训练教练”的完整产品需求。目标是让开发者或代码模型可以据此直接设计、实现和验收功能。

本功能不是让 AI 替代统计系统，也不是训练或微调一个新模型，而是：

> 由本地确定性程序计算事实，由用户配置的模型解释事实、识别趋势并生成可执行的训练建议。

首版必须同时满足：隐私可控、Token 可控、结论有证据、样本不足不武断、AI 失败不影响核心训练。

## 2. 产品目标与非目标

### 2.1 目标

用户完成训练后，系统能够回答：

1. 我当前的准确性、速度和稳定性如何？
2. 最近最需要关注哪些计算范围？
3. 过去的薄弱点是否已经改善？
4. 下一阶段应该练什么、练多少、何时重新评估？

### 2.2 非目标

- 不训练、微调或修改第三方大模型。
- 不让 AI 修改正确答案、评分、原始记录、错题状态或本地统计。
- 不根据少量样本判断用户的性格、智力、粗心程度或学习能力。
- 不要求 AI 每道题实时参与。
- 不把云端 AI 作为训练、统计或 PWA 离线使用的前置依赖。
- 不默认上传逐题原始答案；默认只上传聚合统计。

## 3. 用户价值与核心场景

### 3.1 训练复盘

用户完成若干训练后，查看当前状态、变化原因和下一步计划。

### 3.2 薄弱点迁移

用户过去在除数 `100–199` 错误较多，训练后已改善；最近问题转移到 `200–299`。系统必须同时呈现历史基线和近期表现，而不是只显示一个静态排名。

### 3.3 个性化目标

用户可以选择目标：提高准确率、提高速度、备考冲刺或保持日常练习。相同数据在不同目标下可以产生不同训练建议。

### 3.4 模型可替换

用户可以填写自己的 API Key、Base URL 和模型名称。系统优先支持 OpenAI-compatible Chat Completions 接口，也支持本地 Ollama/LM Studio 等服务。

## 4. 产品形态

新增“能力诊断”页面，包含：

1. **当前水平**：准确性、速度、稳定性、综合状态、数据可信度。
2. **当前重点**：最近最值得训练的 1–3 个范围。
3. **已改善范围**：历史薄弱但近期明显改善的范围。
4. **错误模式**：答案偏大/偏小、空输入、非法输入、超时、重复错误等。
5. **下一步计划**：具体题量、范围比例、重新评估条件。
6. **证据展开**：每条判断展示时间窗口、样本量和计算依据。
7. **分析状态**：上次分析时间、数据是否有变化、下次自动分析条件。

页面必须在没有 AI 配置时提供本地诊断；AI 配置完成后，AI 解释作为增强内容显示。

## 5. 分析原则

### 5.1 事实、推断、建议三分法

所有报告必须按以下顺序输出：

- **事实**：直接由本地数据计算，例如“最近 7 天完成 20 题，错 14 题”。
- **判断**：基于事实的有限推断，例如“该范围近期可能较弱”。
- **建议**：可执行的训练动作，例如“下一组增加该范围到 35%”。

AI 不得把推断写成事实。

### 5.2 三个时间层级

每个指标同时计算：

- **长期基线**：从正式训练数据开始至今。
- **中期表现**：最近 30 天。
- **近期表现**：最近 7 天。

可选增加前一个同长度窗口，例如前 7 天，用于比较趋势。

### 5.3 历史不删除，近期权重更高

旧数据永远保留，用于判断长期能力和改善过程。训练排序以近期表现为主，同时参考长期基线。推荐的排序原则：

1. 近期错误率高；
2. 近期与长期差距大；
3. 样本量达到阈值；
4. 用户当前目标相关。

不得因为近期改善就删除历史薄弱点，也不得因为历史较差而永久强化。

## 6. 统计指标

### 6.1 总体指标

- 题目数、正确数、错误数、正确率；
- 平均、中位数、P75 单题耗时；
- 正确题与错误题的耗时差；
- 最近 7 天、30 天与长期正确率；
- 训练日数、连续训练天数、每次训练题量；
- 训练组之间的波动性；
- 数据完整性和有效样本数。

### 6.2 范围指标

V1 默认按除数百位分桶：`100–199`、`200–299`……`900–999`。每个范围保存：

```ts
interface RangeAggregate {
  rangeMin: number
  rangeMax: number
  lifetimeSamples: number
  lifetimeErrors: number
  lifetimeErrorRate: number
  recent30Samples: number
  recent30Errors: number
  recent30ErrorRate: number
  recent7Samples: number
  recent7Errors: number
  recent7ErrorRate: number
  previous7ErrorRate: number | null
  medianElapsedMs: number | null
  trend: 'improving' | 'worsening' | 'stable' | 'insufficient_data'
}
```

后续可增加具体除数、末位数字、商的小数位等特征，但任何细粒度特征都必须遵守样本阈值。

### 6.3 错误类型

现有记录需要在分析层派生或补充：

- `empty`：空输入；
- `invalid`：非法输入；
- `out_of_tolerance`：超出允许误差；
- `answer_too_large`：用户答案高于正确答案；
- `answer_too_small`：用户答案低于正确答案；
- `slow_correct`：正确但耗时显著高于个人基线；
- `slow_wrong`：错误且耗时显著偏长；
- `repeat_wrong`：同一道题重复错误。

“粗心”“不会”“记忆差”等心理或能力标签禁止作为系统事实。

## 7. 样本、置信度与结论等级

程序先于 AI 决定结论边界，AI 不得自行提高置信度：

| 样本量 | 允许结论 |
|---:|---|
| 0–9 | 数据不足，不得判断 |
| 10–29 | 只能说“初步迹象” |
| 30–59 | 可给出中等可信度判断 |
| 60+ | 可给出较稳定判断 |

如果错误率变化幅度不足 10 个百分点，默认视为稳定；如果近期窗口样本少于 10，道路趋势只能显示“数据不足”。

每条发现必须包含：`sampleCount`、`evidence`、`confidence`、`limitation`。

## 8. 本地增量统计架构

### 8.1 数据流

```text
QuestionRecord
  -> 日聚合 / 范围聚合
  -> 长期、30天、7天指标
  -> 变化检测
  -> 本地诊断报告
  -> 可选 AI 解读
```

### 8.2 新增数据结构

建议新增 `dailyAggregates` 和 `aiAnalysisSnapshots` 两张 IndexedDB 表。

`dailyAggregates` 保存日期、题量、正确数、总耗时和各范围样本/错误数。

`aiAnalysisSnapshots` 保存：

- 分析时间；
- 分析窗口；
- 数据摘要哈希；
- 模型和提示词版本；
- 结构化 AI 结果；
- 消耗估算（若服务商提供）；
- 报告状态。

原始 `QuestionRecord` 继续完整保存，不被聚合表替代。

### 8.3 数据质量过滤

统计只使用正式完成的训练组。必须排除或标记：放弃训练、无效恢复记录、明显异常耗时、重复导入记录。数据质量问题应在报告中显示，而不是静默丢弃。

## 9. AI 调用策略

### 9.1 默认触发条件

同时满足以下条件才自动分析：

- 距离上次 AI 分析至少 24 小时；
- 新增正式题目至少 30 道；
- 数据摘要发生明显变化；
- 用户已启用自动分析并同意上传聚合统计。

每天默认最多 1 次，用户可手动分析。设置中提供关闭自动分析、每日一次、每周一次、新增 30 题后分析和仅手动分析。

### 9.2 明显变化判定

满足任意条件即认为有变化：

- 某范围错误率变化超过 10 个百分点；
- 新出现样本达到阈值的薄弱范围；
- 原薄弱范围错误率下降超过 20%；
- 近期总体正确率变化超过 5 个百分点；
- 训练目标或分析窗口发生变化。

### 9.3 增量请求

AI 不接收全部题目原始记录，默认只接收：长期汇总、最近 30 天汇总、最近 7 天汇总、上次分析后的变化范围、用户目标和上次报告摘要。摘要无变化时直接复用旧报告。

### 9.4 成本控制

- 每日调用上限；
- 单次最大输出 Token；
- 简短/标准/详细报告模式；
- 失败重试不超过 1 次；
- 默认选择低成本模型；
- 调用前展示上传数据范围和预计消耗（可获得时）；
- 记录本地调用次数和估算成本。

## 10. AI 配置

设置页面增加：

- 启用 AI 分析；
- 服务商预设；
- Base URL；
- API Key（密码输入框）；
- 模型名称；
- 自动分析策略；
- 分析窗口；
- 用户训练目标；
- 直连或应用代理模式；
- 测试连接；
- 清除 Key。

统一配置：

```ts
interface AiProviderConfig {
  provider: string
  baseUrl: string
  model: string
  apiKey: string
  enabled: boolean
  consentToUpload: boolean
  autoAnalysis: 'off' | 'daily' | 'weekly' | 'after_30_questions'
  reportDetail: 'short' | 'standard' | 'detailed'
}
```

Key 只保存在本机设置中，永远不得进入 JSON/CSV 导出；清除浏览器数据后允许丢失。直连模式必须提示 Key 会在浏览器网络请求中使用。

## 11. AI 输入与输出契约

### 11.1 输入

输入必须是聚合统计 JSON，不发送逐题原始答案，除非用户明确开启并再次确认。数据必须包含 schema 版本、窗口、样本量和用户目标。

### 11.2 输出

模型必须返回结构化 JSON：

```ts
interface AiFinding {
  type: 'strength' | 'weakness' | 'improving' | 'worsening' | 'insufficient_data'
  title: string
  evidence: string
  sampleCount: number
  confidence: 'low' | 'medium' | 'high'
  limitation: string
  recommendation?: string
}

interface AiReport {
  summary: string
  findings: AiFinding[]
  nextPlan: Array<{
    action: string
    targetRange?: string
    suggestedQuestionCount?: number
    suggestedRatio?: number
    reevaluateAfterQuestions?: number
  }>
  uncertainty: string[]
}
```

## 12. 反过度自信、反谄媚和结果校验

这是首版硬性需求，不能仅依赖提示词。

### 12.1 提示词约束

系统提示词必须要求：

- 事实、判断、建议分开；
- 不得编造数据；
- 不得在样本不足时下结论；
- 不得使用“肯定、一定、完全掌握、绝对没问题”等绝对化表述；
- 不得将错误归因于粗心、智力或性格；
- 不得用无证据的夸奖替代分析；
- 鼓励必须引用实际改善数据；
- 任何结论都要说明限制条件。

### 12.2 程序校验

客户端在渲染前检查：

- 范围是否存在于本地统计；
- 样本量、错误率是否一致；
- 置信度是否超过样本规则允许的等级；
- 建议比例是否在系统上限内；
- 是否出现不存在的事实；
- JSON 是否符合 schema。

校验失败时不展示对应结论，并显示“AI 返回结果无法验证，已使用本地诊断”。

### 12.3 文案策略

推荐：

> 100–199 范围历史错误率为 45%，最近 7 天降至 20%，说明近期表现有所改善；但 200–299 最近 7 天错误率为 70%，建议优先观察该范围。

禁止：

> 你已经完全掌握 100–199，表现非常优秀！

## 13. 训练计划闭环

每条建议必须能转化为训练动作：

```text
发现问题 -> 生成计划 -> 一键开始训练 -> 记录执行情况 -> 对比改善 -> 更新计划
```

计划至少包含：训练组数、每组题量、范围配比、目标指标、复评题量。训练配比仍由确定性出题规则执行，AI 只能提出建议，不能绕过最大强化比例和普通题保留比例。

## 14. 降级与异常处理

以下情况必须保证本地功能正常：未配置 Key、网络失败、CORS、鉴权失败、模型限流、超时、模型返回非法 JSON、服务商不支持结构化输出。

降级顺序：

1. 展示最新有效 AI 报告；
2. 重新计算本地诊断；
3. 显示失败原因和重试入口；
4. 不重复自动重试造成调用浪费。

## 15. 关键验收标准

### 数据与趋势

- 能同时展示长期、30 天和 7 天统计；
- 能识别“历史改善、近期恶化”的范围迁移；
- 增量分析不需要把全部原始题目发送给 AI；
- 放弃训练不进入正式统计。

### 可信度

- 样本不足时不生成确定性薄弱结论；
- 每条发现都显示证据、样本量、可信度和限制；
- AI 编造不存在范围或数值时被拦截；
- AI 谄媚但无证据时，报告仍按本地事实渲染。

### 成本与隐私

- 默认每天最多一次自动调用；
- 数据无明显变化时不调用；
- Key 不被导出；
- 默认只上传聚合统计；
- 无 AI 配置时核心训练与本地统计完整可用。

### 训练闭环

- 建议可一键转换为训练计划；
- 训练结束后能比较计划前后的指标；
- AI 不能修改评分、答案、错题和原始记录。

## 16. 实施顺序

### Phase 1：本地诊断基础

新增日聚合、长期/30天/7天统计、错误类型、趋势和置信度；新增能力诊断页面。不依赖 AI。

### Phase 2：用户模型接入

新增 AI 配置、OpenAI-compatible 客户端、连接测试、结构化输出校验、报告快照和调用冷却。

### Phase 3：训练闭环

将报告建议转换为训练计划，记录执行效果，支持计划复评和动态调整。

### Phase 4：高级能力

支持本地模型、代理模式、目标管理、更多题目特征和跨阶段成长报告。

## 17. 产品最终定义

本功能的核心不是“让 AI 评价用户”，而是：

> 将长期和近期训练数据整合为可信的个人能力变化解释，并把解释转化为可执行、可验证、可持续调整的训练计划。

AI 是可替换的表达和建议组件；本地数据、统计规则、置信度规则、隐私边界和结果校验是产品的核心资产。
